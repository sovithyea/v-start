# Project profile

What this project is and how it wants to be worked on. `/v-start` writes it, and check-ins keep it current. Every command reads it before starting. Personal preferences (yours, not the team's) live in `CLAUDE.local.md`, which is gitignored.

## The project

| | |
|---|---|
| What | A Claude Code plugin that starts any project with a proven agent harness and personalises it to the person and the project. |
| Users | anyone who uses Claude Code (public) |
| Platforms | Claude Code (CLI, desktop app, IDE extensions); no UI |
| People | Vith (owner, approver, reviewer) |
| Stack | Markdown and YAML Claude Code plugin; no app |

## Goals

| | |
|---|---|
| Done looks like | A friend installs v-start, runs /v-start, and gets a working harness without help |
| Deadline | None |
| What matters most | Get it right |

## How agents adapt to this project

- **What matters most** sets the trade-offs. For speed: the smallest slice that ships, with fewer polish passes. For quality: more tests, a design critique on every screen. For learning: explain the why of each step and point to the docs.
- **Platforms** set where every change is checked: 390px first for mobile and web, and the iOS Simulator for Expo.
